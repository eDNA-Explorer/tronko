Sprint review · Pipeline

Where reads were lost

Three bugs on the path from raw FASTQ to a taxonomic call. Each one silently discarded or misassigned reads that were never actually bad.

Case study

One marker, three bugs — each one hiding the next

vert12S · BioScape · same samples throughout, only the pipeline changed

  • vert12S looked like a marker that simply didn’t work: out of a 27M-read run, 1,100 sequences reached assignment and produced 122 taxa.
  • Each fix exposed the one behind it. Trimming spacers recovered the reads — and revealed that almost all of them were being scored against the wrong strand.

Why this matters beyond one marker

  • Stage 1 is indistinguishable from “this marker didn’t amplify well.” Nothing failed loudly — the reads were quietly discarded upstream.
  • The two bugs below are what stage 2 and stage 3 turned out to be, and both reach markers well beyond vert12S.
01

Heterogeneity spacers broke the primer anchor

Demultiplexing

  • Some preps insert 1–8 random bases between adapter and primer, to raise base diversity on the flow cell.
  • ^PRIMER requires the primer at position 0 — a spacered read never matches.
  • Nearly every read lands in unknown.

Why not just drop the anchor?

  • Primers aren’t unique to their own marker.
  • ITS5 (ITS1 forward) sits in the 3′ end of the 18S gene — inside what Euk1391f → EukBr amplifies.
  • Unanchored, cutadapt matches it mid-read and files an 18S read under ITS1.
  • It occurs internally in 32,892 of 362,046 18S reference amplicons — 9.1% — at a median 103 bp into a 132 bp amplicon.

02

Reverse-strand reads were scored against the wrong strand

Alignment

  • Where the reference stores the amplicon in the opposite orientation, every read arrives reverse-complemented.
  • The aligner flagged the strand correctly — but scoring got the read unchanged.
  • Each read was compared base-for-base against its own reverse complement.
  • Synthetic data couldn’t catch this. Simulated reads are built forward off the reference (forward_primer + amplicon + …), so every hit returns forward-strand and the reorientation path never runs. The trigger is a property of the reference database, not of the reads.

03

The top-hits cap didn’t survive the move from BWA to minimap2

Placement

  • The aligner swap handed our existing --max-leaf-matches cap straight to minimap2 as best_n.
  • The number carried over, the meaning didn’t: under BWA it bounded a list of genuine top hits; under minimap2 it only bounds how many alignments come back, however much worse they score.
  • Every returned hit then voted in the consensus. We now apply the cap on score, so it means what it always meant.

04

Both fixes, measured against known truth

Validation · 4 markers · synthetic communities

  • Same reads, same reference, same parameters — only the binary changes (f3bdfac → 530caf9).
  • Every read carries a known source species, so each assignment is scored as closer to or further from truth.
  • §02 is now testable. Simulated reads are built forward off the reference, so the reorientation path never ran. Reverse-complementing the query before placement reproduces the broken condition — and it reproduces the production signature exactly (32–34% mismatch, matching the 36% seen on real vert12S).

Reading these numbers

  • vert12S is 3 independent communities; the other three are 1 each — direction is replicated, magnitude is not yet.
  • Reference is a held-out build (30% of species removed), so absolute F1 is deliberately low. The deltas are the result, not the levels.
  • ASV F1 scores each ASV at its own deepest truthful rank — for a held-out species the right answer is genus, so naming a species anyway counts against you.
  • Re-running the same binary twice is byte-identical, so no delta above is run-to-run noise.
05

The same fixes on production data

3 projects · 8 marker runs · 31.5M paired reads re-assigned

  • Every project re-run on identical reads — same QC output, same reference. Only the binary changed.
  • The strand fix fired on vert12S alone. Every other marker’s mismatch rate is flat before → after, so their movement is the cap fix by itself.
  • Mean assignment depth rose on 8 of 8 marker runs, and distinct taxa rose on 7 of 8.

Reading these numbers

  • Production has no ground truth. These tables show what moved, not whether it moved correctly — §04 is what establishes the direction.
  • Depth rising is consistent with the cap change: dropping worse candidates shrinks the consensus set, so the answer resolves further down the lineage.
  • Paired partition only (>90% of reads); the unpaired partitions lack the mate-length columns needed for the mismatch comparison.
